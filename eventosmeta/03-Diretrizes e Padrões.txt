## Filosofia de Desenvolvimento

### Abordagem
- **Pragmático:** Foco em soluções práticas e aplicáveis
- **Proativo:** Sempre pensar no próximo passo
- **Estratégico:** Planejamento de longo prazo
- **Incremental:** Construir conhecimento progressivamente
- **Passo a passo:** Uma solução por vez (não múltiplas alternativas)

### Princípios
1. Resolver app por app e testar na sequência
2. Não inventar dados ou informações
3. Confirmar antes de implementar decisões importantes
4. Ser claro sobre limitações
5. Sempre sugerir próximos passos

class NomeDoModel(models.Model):

    # Campos obrigatórios primeiro

        # Validações customizadas antes de salvar

### Validações
```python
from django.core.exceptions import ValidationError

class Inscricao(models.Model):
    # ... campos ...
    
    def clean(self):
        """Validações customizadas."""
        # Verificar se já existe inscrição
        if Inscricao.objects.filter(
            evento=self.evento,
            interessado=self.interessado
        ).exclude(pk=self.pk).exists():
            raise ValidationError('Já existe inscrição neste evento.')
    
    def save(self, *args, **kwargs):
        self.full_clean()  # Executa clean()
        super().save(*args, **kwargs)
```

## Padrões de Views

### Function-Based Views (FBVs)
```python
from django.shortcuts import render, get_object_or_404, redirect
from django.contrib.auth.decorators import login_required
from django.contrib import messages

@login_required
def detalhe_evento(request, evento_id):
    """Exibe detalhes de um evento."""
    evento = get_object_or_404(Evento, pk=evento_id)
    
    context = {
        'evento': evento,
        'inscricoes_abertas': evento.status.codigo == 'INSCRICOES_ABERTAS'
    }
    
    return render(request, 'eventos/detalhe.html', context)
```

def lista_classificacao(request, evento_id):

### Quando Usar
- Lógica de negócio complexa
- Operações que envolvem múltiplos models

### Estrutura de Service
```python
# apps/selecao/services.py

from django.db import transaction
from apps.eventos.models import Evento, EventoCriterio
from apps.selecao.models import Inscricao, Classificacao

class ClassificadorService:
    """
    Service responsável pela classificação de inscrições.
    
    Centraliza toda a lógica de pontuação e ordenação.
    """
    
    @staticmethod
    @transaction.atomic
    def classificar_evento(evento: Evento) -> dict:
        """
        Classifica todas as inscrições de um evento.
        
        Args:
            evento: Instância do evento a classificar
            
        Returns:
            dict com estatísticas da classificação
        """
        # Limpar classificações anteriores
        Classificacao.objects.filter(inscricao__evento=evento).delete()
        
        # Buscar inscrições válidas
        inscricoes = Inscricao.objects.filter(
            evento=evento,
            status__codigo__in=['PENDENTE', 'APROVADA', 'CONFIRMADA']
        ).select_related('interessado')
        
        # Processar cada inscrição
        for inscricao in inscricoes:
            pontuacao = ClassificadorService._calcular_pontuacao(
                inscricao, 
                evento
            )
            ClassificadorService._criar_classificacao(
                inscricao, 
                pontuacao
            )
        
        # Definir posições
        ClassificadorService._atualizar_posicoes(evento)
        
        return {
            'total_inscricoes': inscricoes.count(),
            'classificados': Classificacao.objects.filter(
                inscricao__evento=evento,
                classificado=True
            ).count()
        }
    
    @staticmethod
    def _calcular_pontuacao(inscricao, evento):

@admin.register(Evento)
class EventoAdmin(admin.ModelAdmin):
    actions = ['classificar_inscricoes', 'exportar_classificacao']
    
    @admin.action(description='Classificar inscrições dos eventos selecionados')
    def classificar_inscricoes(self, request, queryset):
        """Classifica inscrições de eventos selecionados."""
        total = 0
        for evento in queryset:
            resultado = ClassificadorService.classificar_evento(evento)
            total += resultado['classificados']
        
        self.message_user(
            request,
            f'{total} inscrições classificadas com sucesso.',
            level=messages.SUCCESS
        )
```

### Exportação para Excel/CSV
```python
import csv
from django.http import HttpResponse

@admin.action(description='📊 Exportar classificação detalhada (Excel)')
def exportar_classificacao_excel(self, request, queryset):
    """Exporta classificação com detalhes."""
    response = HttpResponse(content_type='text/csv; charset=utf-8-sig')
    response['Content-Disposition'] = 'attachment; filename="classificacao.csv"'
    response.write('\ufeff')  # BOM para Excel
    
    writer = csv.writer(response, delimiter=';')
    writer.writerow(['Evento', 'Posição', 'Nome', 'CPF', 'Pontos'])
    
    for evento in queryset:
        classificacoes = Classificacao.objects.filter(
            inscricao__evento=evento
        ).select_related(
            'inscricao__interessado'
        ).order_by('posicao')
        
        for c in classificacoes:
            writer.writerow([
                evento.nome,
                c.posicao,
                c.inscricao.interessado.nome,
                c.inscricao.interessado.cpf,
                c.pontuacao_total
            ])
    
    return response
```

## Tratamento de Erros

### Try-Except em Services
```python
class ClassificadorService:
    @staticmethod
    def classificar_evento(evento):
        try:
            # Lógica de classificação
            resultado = processar_classificacao(evento)
            return resultado
            
        except Evento.DoesNotExist:
            raise ValueError(f'Evento {evento.id} não encontrado')
            
        except Exception as e:
            # Log do erro
            import logging
            logger = logging.getLogger(__name__)
            logger.error(f'Erro ao classificar evento {evento.id}: {str(e)}')
            raise
```

## Boas Práticas

### DRY (Don't Repeat Yourself)
- Evitar código duplicado
- Usar service layer para lógica reutilizável
- Criar mixins para funcionalidades comuns

### KISS (Keep It Simple, Stupid)
- Soluções simples primeiro
- Não otimizar prematuramente
- Código legível > código "inteligente"

### YAGNI (You Aren't Gonna Need It)
- Implementar apenas o necessário agora
- Não adicionar funcionalidades "por precaução"
- Evoluir conforme demanda real

### Single Responsibility
- Cada classe/função com uma responsabilidade
- Models cuidam de dados
- Services cuidam de lógica
- Views cuidam de requisição/resposta
