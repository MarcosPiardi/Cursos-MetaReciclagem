# Projeto - Requisitos e Funcionalidades
**Sistema:** MetaReciclagem - Gestão de Eventos e Cursos
**Última atualização:** 12/12/2025

---

## Visão Geral do Projeto

Sistema de gestão de eventos, cursos e inscrições para o programa MetaReciclagem da prefeitura, com foco em classificação automatizada de candidatos baseada em critérios sociais e educacionais configuráveis.

### Objetivo
Gerenciar todo o ciclo de vida de eventos e cursos oferecidos pela MetaReciclagem, desde a divulgação até a emissão de certificados, com transparência no processo de seleção.

---

## Requisitos Funcionais

### R01 - CADASTRO E MANUTENÇÃO DE USUÁRIOS DO SISTEMA
**Descrição:** Cadastrar usuários que operacionalizarão o sistema.

**Características:**
- Representa os operadores do sistema (staff)
- Níveis de acesso diferentes (admin, staff)
- Dados básicos de contato e identificação
- Apenas admin pode criar novos usuários
- Campos: nome, CPF, email, telefone, setor

**Status:** ✅ Implementado

---

### R02 - CADASTRO E MANUTENÇÃO DE NÍVEL DE ACESSO
**Descrição:** Cadastrar diferentes níveis de acesso dos usuários.

**Níveis:**
- **Admin (Superuser):** Acesso total ao sistema
- **Staff:** Acesso a operações administrativas (sem editar superusers)
- **Interessado:** Acesso limitado (visualização e inscrição)

**Gestão:**
- Incorporado ao admin do Django (Groups e Permissions)
- Apenas admin pode alterar permissões

**Status:** ✅ Implementado

---

### R03 - CADASTRO E MANUTENÇÃO DE INTERESSADOS
**Descrição:** Cadastro de pessoas interessadas em cursos da MetaReciclagem.

**Dados Pessoais:**
- Nome completo
- CPF (único, usado para login)
- Data de nascimento
- Sexo
- Fototipo (cotas raciais)
- Escolaridade

**Localização:**
- Endereço completo (logradouro, número, complemento)
- Bairro, cidade, UF, CEP

**Características Sociais:**
- Programa social (sim/não)
- NIS (Número de Identificação Social) - **só aparece se programa_social=True**
- Necessidades especiais (sim/não)
- Tipos de deficiência - **só aparecem se necessidades_especiais=True:**
  - Física
  - Visual
  - Auditiva
  - Intelectual
  - Psicossocial
  - Múltiplas

**Dados de Contato:**
- Telefone, Celular (obrigatório)
- Email

**Responsável (opcional - para menores):**
- Nome do responsável
- Contato do responsável
- Telefone do responsável
- Celular do responsável
- Email do responsável

**Autenticação:**
- Login via CPF + senha
- Acesso ao dashboard pessoal

**Status:** ✅ Implementado

**Funcionalidades:**

### R05 - CADASTRO DE EVENTO/CURSO
**Descrição:** Cadastrar eventos/cursos disponibilizados para a população.

**Informações do Evento:**
- Nome
- Descrição
- Conteúdo programático
- Requisitos (pré-requisitos)
- Vagas totais
- Vagas reservadas (cotas)
- Local

**Cronograma:**
- Período de inscrições (data início/fim)
- Período de matrículas (data início/fim)

- Horários (dias da semana + hora início/fim)
- Instrutor/Professor

**Critérios de Classificação:**
- Configuráveis por evento
- Cada critério com peso/pontos
- Prioridade de aplicação (1, 2, 3...)
- Tipo: PONTUACAO ou ORDENACAO

**Status:** ✅ Implementado

**Informações da Turma:**

**Gestão:**

- Lançar frequência
- Lançar notas

- Emitir certificados

**Status:** ✅ Implementado

---

### R08 - GERAR CLASSIFICAÇÃO DOS INTERESSADOS
**Descrição:** Após período de inscrições, classificar interessados conforme critérios.

**Processo:**
1. Staff aciona classificação no admin
2. Sistema calcula pontuação de cada inscrição
3. Aplica critérios de ordenação
4. Define posição final
5. Marca classificados vs lista de espera
6. Registra critérios atendidos

**Características:**
- Automático via `ClassificadorService`
- Baseado em critérios configurados no evento
- Considera prioridade dos critérios
- Transparente (exporta detalhes)

**Status:** ✅ Implementado

---

### R09 - CADASTRO DE CRITÉRIOS DE CLASSIFICAÇÃO
**Descrição:** Cadastrar critérios para transparência no processo de seleção.

**Tipos de Critérios:**

#### Critérios de PONTUACAO
| Código | Nome | Categoria | Pontos Padrão |
|--------|------|-----------|---------------|
| PCD | Pessoa com Deficiência | DEFICIENCIA | 10 |
| NIS | Programa Social | SOCIAL | 5 |
| JOVEM_16_24 | Jovem (16-24 anos) | FAIXA_ETARIA | 5 |
| IDOSO_50 | Idoso (50+ anos) | FAIXA_ETARIA | 5 |
| COTA_RACIAL | Cota Racial | SOCIAL | 5 |
| ESC_FUND_INC | Ens. Fund. Incompleto | ESCOLARIDADE | 3 |
| ESC_FUND_COMP | Ens. Fund. Completo | ESCOLARIDADE | 3 |
| ESC_MEDIO_INC | Ens. Médio Incompleto | ESCOLARIDADE | 2 |
| ESC_MEDIO_COMP | Ens. Médio Completo | ESCOLARIDADE | 2 |

#### Critérios de ORDENACAO
| Código | Nome | Descrição |
|--------|------|-----------|
| IDADE_CRESCENTE | Idade Crescente | Mais jovem primeiro |
| IDADE_DECRESCENTE | Idade Decrescente | Mais velho primeiro |
| ORDEM_INSCRICAO | Ordem de Inscrição | Cronológica |

**Configuração por Evento:**
- Escolher quais critérios aplicar
- Definir prioridade (ordem de aplicação)
- Ajustar pontos se necessário

**Status:** ✅ Implementado

## Regras de Negócio

### RN01 - Inscrições
- Um interessado pode se inscrever em múltiplos eventos
- Não pode se inscrever duas vezes no mesmo evento
- Só pode se inscrever durante período de inscrições abertas

### RN02 - Classificação
- Classificação é automática após inscrições encerradas
- Critérios aplicados na ordem de prioridade
- Pontuação calculada conforme critérios atendidos
- Desempate por critérios de ordenação

### RN03 - Vagas
- Vagas podem ser gerais ou reservadas (cotas)
- Sistema respeita percentual de reserva
- Lista de espera criada automaticamente

### RN04 - Matrículas
- Apenas classificados podem ser matriculados
- Matrícula confirma vaga
- Desistência libera vaga para lista de espera

### RN05 - Certificados
- Apenas alunos aprovados recebem certificado
- Aprovação depende de frequência E nota mínima

## Fluxos de Processo

### Fluxo Principal: Ciclo de um Evento

```
1. Staff cria Evento
   ├─> Define critérios de classificação
   ├─> Define vagas e cotas
   └─> Define cronograma

2. Status: Inscrições Abertas
   └─> Interessados se inscrevem via web

3. Status: Inscrições Encerradas
   └─> Staff aciona classificação

4. Sistema classifica automaticamente
   ├─> Calcula pontuação
   ├─> Aplica ordenação
   └─> Define classificados vs lista espera

5. Status: Matrículas Abertas
   ├─> Staff contata classificados
   └─> Matricula interessados confirmados

6. Status: Em Andamento
   ├─> Staff lança frequência
   └─> Staff lança notas

7. Status: Encerrado
   └─> Sistema gera certificados (aprovados)
```

## Tipos de Usuários

### 1. Admin (Superuser)
**Permissões:**
- Acesso total ao sistema
- Criar/editar usuários
- Alterar permissões
- Acessar todas as funcionalidades

**Uso:**
- Configuração inicial
- Gestão de usuários
- Auditoria

### 2. Staff
**Permissões:**
- CRUD de eventos/cursos
- Configuração de critérios
- Classificação de inscrições
- Montagem de turmas
- Lançamento de notas/frequências
- Exportação de dados

**Restrições:**
- Não pode criar superusers
- Não pode alterar permissões

### 3. Interessado
**Permissões:**
- Cadastro próprio
- Login com CPF
- Visualização de eventos abertos
- Inscrição em eventos
- Dashboard pessoal
- Acompanhamento de status

**Restrições:**
- Não acessa área administrativa
- Não vê dados de outros interessados

- Tempo médio de classificação < 5 minutos
